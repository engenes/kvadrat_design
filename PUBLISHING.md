## Известные сбои и границы

- Итерация Select 22 сентября: проверен и отправлен в source `main` коммит `e170e803931cee84d01266c1cee3f4da478bfa18` (`feat(web): add branded joined select controls`). Текущий объединённый `save_version_and_deploy_private` вызван с обязательным архивом из этого SHA; upload завершился тайм-аутом после 60003 ms до сохранения версии. Размер `.sites-runtime/select-release.tar` — 47 943 680 байт. `saved_version_id` не возвращён; последующая проверка показала прежнюю v9. **Select ещё не опубликован**. Не отправлять source повторно без новых изменений и не считать успешный push публикацией. После устранения транспорта сохранить/опубликовать этот SHA и сверить deployment. Повторную загрузку или пропуск обязательного архива в этой попытке не выполняли.

- Загрузка локального архива через параметр `archive` неоднократно завершалась тайм-аутом около 60 секунд на blob upload. Проверялись tar и tar.gz. Последний архив весил 43 588 570 байт; повторная смена упаковки не является новым решением. Причина сбоя транспорта не установлена.
- После этого `save_site_version` без `archive` и `deploy_private_site_version` публиковали тот же отправленный SHA успешно. Это проверенный результат, а не утверждение, что сервис архивов никогда не работает.
- В инструкции инструментов, прочитанной 22 сентября, архив обязателен, если его можно собрать локально. **Сбой загрузки не равен невозможности сборки архива.** Поэтому безусловное правило «всегда пропускать archive» не вводится. Если текущий контракт не допускает предпочтительный путь, назвать это ограничение и выбрать только разрешённый вариант; не повторять безрезультатные попытки вслепую.
- Допустимость пути проверять до push. Если архив по контракту обязателен, пользователь запретил повторять прежнюю загрузку, а доступного разрешённого варианта нет, сообщить этот конкретный конфликт и оставить публикацию незавершённой. Не выдавать предпочтение или прошлый успешный вызов за отмену текущего требования.
- `publish_on_push: "private"` был запрошен при публикации v9; ответ — `publish_on_push_accepted: false`. Автопубликация после push для этого проекта не подтверждена. Не рассчитывать на неё и не тестировать заново каждый раз без изменения условий.
- Текущий объединённый инструмент `save_version_and_deploy_private` предписан вместо двух вызовов для новой версии приватного сайта, если он доступен. Его условие по архиву такое же; сам по себе он не устраняет сбой загрузки. Уже сохранённую версию повторно не сохранять.
- Для Git на этом Windows-хосте рабочий способ — PTY + `Read-Host -AsSecureString` + временный `http.extraHeader`. Попытка читать токен через `Console.ReadLine()` без PTY возвращала null. Токены в файлы и историю Git не записывать.

Повторно диагностировать архив имеет смысл по прямому запросу пользователя, при подтверждённом изменении среды/инструмента или при обязательном требовании более высокого уровня. При обычной публикации начинать с этой записи, а не с повторного поиска уже проверенных способов.
