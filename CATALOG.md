# Каталог из локального экспорта Figma

Источник: `АН КВАДРАТ (Copy)`, страница `Page 1`, фрейм `Catalog` (`49:0`), 1920 × 4460. Экспорт Local Figma Reader от 14 сентября 2026, 19:54:46 UTC: 503 слоя, 20 карточек, четыре исходных изображения и превью. SHA-256 источника и изображений записаны в `dist/catalog-page/provenance.json`. Вызовы Figma MCP и REST API для этого переноса не использовались.

Рабочая страница — `property-catalog.html`. Она доступна из бокового меню библиотеки и по ссылке «Все объекты» на главной. Это продолжение отдельного проекта Sites; приложение Laravel/Nuxt не изменялось.

## Устройство

- `homepage/cards.js`: одна функция `propertyCard` для главной, галереи и каталога. Наличие `walls` выводит материал стен; старые карточки главной сохраняют поле сдачи. Цена за метр берётся из данных макета, а не вычисляется заново.
- `homepage/search-fields.js`: общие пять полей поиска, одинаковые имена и варианты. Главная использует компактную форму, каталог добавляет диапазоны цены, площади и этажа, материал стен и переключатель ремонта.
- `homepage/sections.js`, `ui.js`: общие шапка, контакты, подвал и кнопки. Светлая шапка и контакты каталога передаются параметрами, тексты главной сохранены.
- `catalog-page/data.js`: данные карточек и тексты, извлечённые из JSON. Повторяющиеся карточки сохранены в порядке макета; дополнительные записи не выдумывались.
- `catalog-page/components.js`: композиция каталога, фильтра, карты, баннера и текстового раздела.
- `catalog-page/model.js`: фильтрация, сортировка и пагинация без зависимости от DOM.
- `catalog-page/interactions.js`: работа формы, результатов и диалогов.
- `catalog-page/styles.css`: оформление и адаптив каталога поверх общих компонентов.

HTML собирается заранее: содержимое доступно без JavaScript. Layout использует обычный поток документа, CSS Grid/Flex, media queries и относительные размеры; JS не выбирает мобильный шаблон. Абсолютное позиционирование используется для декора, кадрирования и кнопки внутри карточки. Нативные select/input, fieldset/legend, details/summary и dialog сохраняют стандартное управление. Диалоги закрываются Escape, фокус возвращается к открывшему элементу, ошибки и изменение количества объявляются через live regions. Учитывается reduced motion. Страница макета помечена `noindex,nofollow`.

Подход сверялся с [документацией CSS Grid](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout) и [HTML dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog).

## Изображения

Три оригинала уже были в библиотеке и совпали по SHA-256: два интерьера и фотография новостроек. Они используются по существующим путям. Добавлены только изображение карты и превью фрейма. Кадрирование карты и баннера воспроизведено через CSS по `imageTransform` из JSON; файлы не перерисовывались.

SVG-контуры не вошли в выгрузку. Значки фильтра найдены в CSS оригинального сайта: `calculator.svg`, `home.svg`, `calendar.svg`, `plans.svg`, `pin.svg`. Недостающие `calculator.svg` и `calendar.svg` загружены без изменения с `https://novostrojki-orenburga.ru/sites/all/themes/kvadrat/img/`; остальные уже были сохранены на главной. Стрелки, логотип и декоративные изображения также переиспользованы. В общих полях поиска текстовые символы заменены этими значками.

## Проверки

В браузере проверены ширины 320, 390, 768, 1024 и 1920 CSS px. На проверенных размерах ширина документа равна доступной ширине viewport, горизонтального переполнения нет. Сетка перестраивается с четырёх колонок в две и одну.

При ширине 1920 начала фильтра (371), карты (713), первой карточки (936), баннера (2135), раздела помощи (3350) и подвала (3942) соответствуют координатам источника. Размер карточки 270 × 350, фото 270 × 169, межколоночный интервал 21, между рядами 40. Это проверка геометрии, а не заявление о попиксельной идентичности. Текстовое сглаживание, некоторые оттенки и декоративные слои могут отличаться.

Проверены: 10 однокомнатных объектов; 5 карточек с кирпичными стенами; пустая выборка; ошибка обратного диапазона цены; сброс; сортировка цены в обе стороны; 12 объектов на первой странице и 8 на второй; просмотр объекта и карты; Escape и восстановление фокуса; проверка демонстрационной формы. Ошибок JS в проверенных сценариях не обнаружено. На главной повторно проверены поиск по комнатам и открытие карточки. После исправления контактов проверяется также подвал на планшете.

Команды из корня отдельного сайта:

```text
node scripts/build-homepage.mjs
node scripts/build-homepage-gallery.mjs
node scripts/build-catalog.mjs
node scripts/verify-catalog.mjs
node scripts/verify.mjs
node scripts/verify-builder.mjs
```

`verify-catalog.mjs` проверяет данные реальной выгрузки, фильтры, диапазоны, сортировку без мутации, пагинацию, обе версии общей карточки, общий фильтр в двух страницах, ссылки, синтаксис и контрольные суммы изображений. Остальные проверки сохраняют 167 оригинальных файлов библиотеки и работоспособность модели конструктора.

Повторный импорт этого фрейма: `node scripts/import-catalog.mjs "полный путь к .figma-reader.json"`, затем сборка каталога. Импортёр специально привязан к структуре этого старого макета и останавливается при отсутствии ожидаемых полей; это не универсальная генерация HTML из любой Figma.

## Ограничения интерактивного макета

- В источнике нарисовано «56 объектов» и несколько страниц, но присутствуют только 20 карточек. Рабочий счётчик показывает 20. Можно выбрать 20 либо 12 записей на странице; дополнительные 36 объектов не создаются. Надпись «76 предложений» в рекламном баннере оставлена как текст дизайна.
- Дат размещения нет. Кнопка «по дате добавления» возвращает порядок карточек исходного макета. Цена сортируется по значениям карточек.
- Нет сведений о районе и ремонте: при выборе этих условий отображается объяснение отсутствия данных. Типы недвижимости и рынки, отсутствующие в выгрузке, возвращают пустую выборку.
- Карта — сохранённое изображение с возможностью открыть его целиком. Географических координат и интерактивных маркеров нет, фильтры не подменяют точки карты.
- Исходный мобильный фрейм не приложен; адаптив разработан по структуре широкого экрана.
- Данные, телефоны и цены воспроизводят старый макет. CRM/API не подключены, формы ничего не отправляют и не сохраняют.
